# Lesson 5 — Terraform-інфраструктура на AWS

Цей проєкт розгортає базову інфраструктуру на AWS за допомогою Terraform:

- **Віддалений бекенд** для стейтів (S3 та DynamoDB для блокування).
- **Мережу (VPC)** з публічними та приватними підмережами.
- **ECR** (Elastic Container Registry) для зберігання Docker-образів.

Регіон за замовчуванням — `us-west-2`.

## Опис модулів

### `s3-backend`
Створює централізоване та безпечне сховище для стейт-файлів Terraform:

- **S3-бакет** із увімкненим **версіюванням** (історія стейтів), **шифруванням** (AES256) та повним блокуванням публічного доступу.
- **DynamoDB-таблиця** `terraform-locks` (режим `PAY_PER_REQUEST`, ключ `LockID`) для **блокування стейтів**, щоб уникнути одночасних змін.
- **Outputs:** ім'я та URL S3-бакета, ім'я DynamoDB-таблиці.

### `vpc`
Створює мережеву інфраструктуру:

- **VPC** з CIDR `10.0.0.0/16`.
- **3 публічні** та **3 приватні** підмережі у трьох зонах доступності.
- **Internet Gateway** для вихідного трафіку публічних підмереж.
- **NAT Gateway** (один, з Elastic IP) для вихідного трафіку приватних підмереж.
- **Route Tables** та їхні асоціації: публічні → IGW, приватні → NAT.
- **Outputs:** `vpc_id`, ID публічних та приватних підмереж.

### `ecr`
Створює репозиторій для Docker-образів:

- **ECR-репозиторій** `lesson-5-ecr` з автоматичним **скануванням образів під час push** (`scan_on_push`).
- **Політика доступу** до репозиторію (за замовчуванням — root поточного акаунта).
- **Lifecycle-політика** для очищення старих/невикористовуваних образів.
- **Output:** URL репозиторію.

## Передумови

- Встановлений [Terraform](https://developer.hashicorp.com/terraform/downloads) (>= 1.5).
- Налаштований доступ до AWS (`aws configure` або змінні середовища `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`).

## ⚠️ Важливо: порядок першого запуску (bootstrap)

`backend.tf` посилається на S3-бакет і DynamoDB-таблицю, які створює **сам** модуль `s3-backend`. На чистому акаунті цих ресурсів ще немає, тому **перший** `terraform init` з активним бекендом завершиться помилкою.

Одноразова послідовність запуску:

1. Тимчасово **закоментуйте** блок `terraform { backend "s3" { ... } }` у `backend.tf`.
2. Створіть бекенд-ресурси локально:
   ```bash
   terraform init
   terraform apply -target=module.s3_backend
   ```
3. **Розкоментуйте** блок бекенду в `backend.tf`.
4. Перенесіть стейт у S3:
   ```bash
   terraform init -migrate-state
   ```
5. Далі працюйте як звичайно (`terraform apply` для решти ресурсів).

Після цього стейт зберігається у S3 і блокується через DynamoDB.

## Команди

```bash
# Ініціалізація (завантаження провайдерів та налаштування бекенду)
terraform init

# Перегляд плану змін
terraform plan

# Застосування змін
terraform apply

# Видалення всієї інфраструктури
terraform destroy
```

> Щоб видалити все, включно з бекенд-ресурсами, спершу знову закоментуйте блок бекенду й виконайте `terraform init -migrate-state` (перенесення стейту назад локально), а потім `terraform destroy`. Інакше Terraform не зможе видалити бакет, у якому лежить активний стейт.
